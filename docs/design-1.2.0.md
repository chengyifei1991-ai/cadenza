# Cadenza 1.2.0 设计（运营与治理特性包）

> 状态：**设计待评审**（2026-09-29）｜ 前置：1.1.0 已定版（tag `v1.1.0`）
> 约束：不破坏 1.1.0 对外协议面（既有端点语义不变，仅新增端点/参数/字段）；
> 新机制默认关闭或对既有单管理员部署零影响；每一项独立可测、可单独发布。

## 1. 目标与范围

1.1.0 解决的是"**变更能不能落地并被证明生效**"；1.2.0 解决"**谁在改、改到哪一步、能不能分权与批量**"。

范围收敛自三处：`product-plan` §6 的 1.2.0 行、1.1.0 复评遗留（F-18/F-19）、1.1.0 明确延后项（SSE/暗色/EN）。

| 包 | 内容 | 价值 | 风险 | 依赖 |
|---|---|---|---|---|
| **C-a** | 任务状态流转时间线（复用 `task_events`） | 中 | 低 | 无（数据已存在） |
| **C-b** | 审计导出（CSV / JSON） | 中 | 低 | 无 |
| **C-c** | 遗留收尾：F-18 中间态超时巡检、F-19 `stats/ops` SQL 聚合 | 低 | 低 | 无 |
| **C-d** | **RBAC**：多用户 + 角色（admin/approver/viewer）+ 授权中间件 + 审计 actor 真实化 | **高** | 中高 | C-a 的 actor 展示 |
| **C-e** | 分组管理 UI + 分组选择器下发 + 批量下发 | 高 | 中 | C-d（权限边界） |
| **C-f** | 体验补强：暗色模式、EN 快速开始 | 中 | 低 | 无 |

**明确不在 1.2.0**：多实例联邦/状态共享、Helm、插件化、告警联动（1.3.0）；SSE 流式输出（见 §6）。

## 2. 设计决策

- **D1｜时间线数据源就是 `task_events`**：不新增埋点、不做双写；1.1.0-e 已按状态机迁移点落事件，
  时间线只是"把已有事实读出来"，避免第二份真相。
- **D2｜导出在服务端流式写出**：`GET /api/v1/audit/export?format=csv|json`，复用既有筛选参数
  （`action`/`actor`/`from`/`to`），带**行数上限**（默认 10 万，超出返回 400 并提示收窄筛选）；
  不复用分页游标（导出语义是"全量快照"，分页会给出一份静默截断的假全量）。
- **D3｜中间态巡检只做"发现与收口"**：巡检把超时仍停在 `applying`/`validating` 的任务标记为
  `failed` 并写明原因，**不改状态机主流程**、不做自动重试（重试语义应由使用方决定）。
- **D4｜RBAC 是可选叠加**：未创建多用户时，行为与 1.1.0 **完全一致**（单管理员 + 现有登录）；
  启用多用户后，权限判定收敛到服务端中间件（前端只做展示态收敛，不作为安全边界）。
- **D5｜角色取最小集**：`admin`（全权）/ `approver`（审批、下发、回滚）/ `viewer`（只读）。
  MCP token 映射为 `admin`（默认）或 `approver`（可配），保持 1.1.0 的 `/mcp` 契约不变。
- **D6｜批量下发 = N 个独立任务**：不引入批次聚合状态机；前端以批次标签聚合展示，
  单个失败不影响其余，审计逐条留痕（沿用"每个变更独立可追溯"的既有口径）。
- **D7｜凭据继续 fail-closed**：RBAC 的用户口令哈希、会话密钥等敏感值一律由部署方以环境变量提供，
  缺失即拒绝启动（沿用 v1.1.0 的 `LLM_API_KEY` 契约，不留占位兜底）。

## 3. 逐项设计（概要）

### 3.1 C-a 任务状态流转时间线

- 存储：`ListTaskEventsByTask(ctx, taskID)`（`WHERE task_id=? ORDER BY id ASC`，带上限）。
- REST：`GET /api/v1/tasks/{id}/events` → `{task_id, items:[{id,from_status,to_status,created_at}], total}`；
  未知任务 404，非 GET 405。**只读**，不改任务服务。
- 前端：任务详情页新增「状态流转」时间线（antd `Timeline`）：创建 → 待审批 → 下发中 → 终态，
  相邻事件之间显示**间隔时长**（复用 `fmtDurationMs`），终态失败时同步展示任务 `error`。
- 语义：时间线是**事实回放**（事件表就是写时落下的），不基于任务当前状态反推，避免"状态被改过就看不出来"。

### 3.2 C-b 审计导出

- `GET /api/v1/audit/export`：`format=csv`（默认）｜`json`；`Content-Disposition: attachment`，
  文件名带时间戳；CSV 带表头（`id,created_at,actor,action,target,detail`），UTF-8 BOM 便于 Excel 打开。
- 上限与错误语义：超过 `limit`（默认 100000，可参数下调）→ 400；非法 `format`/时间参数 → 400（复用既有校验）。
- 审计**不裁剪**：导出内容与页面一致（不做脱敏转换），但**记录一条 `export` 动作**，导出本身也可审计。

### 3.3 C-c 遗留收尾

- **F-18 中间态超时巡检**：后台定时（默认 60s，可关）扫描 `updated_at` 超过阈值（默认 5m）仍处于
  `applying`/`validating` 的任务 → 置 `failed` + `error="任务超时未收到生效确认（巡检收口）"` + 审计；
  阈值与开关走配置，默认开启但**只处理明确超时的中间态**，不触碰正常流转。
- **F-19 `stats/ops` SQL 聚合**：把窗口内任务的终态分布与成功率改为 `GROUP BY status` 单查询聚合，
  事件仍按任务聚合（时长分位数需要跨行计算）；给出大窗口（90 天）基准对比，确保量级退化可控。

### 3.4 C-d RBAC（1.2.0 中心项）

- 数据模型：`users(id, username, password_hash, role, created_at, disabled_at)`；
  `web_sessions` 增 `user_id`（幂等迁移，旧会话映射为 admin）。
- 认证：既有登录改为查 `users`；`WEB_ADMIN_USER`/`WEB_ADMIN_PASSWORD_HASH` 保留为**引导管理员**
  （首次启动落库，兼容 1.1.0 部署方式）。
- 授权：服务端中间件按"方法 + 路径"映射到最小角色（读=viewer、审批/下发/回滚=approver、用户管理=admin），
  未授权 403 中文错误；`/mcp` 沿用 token 映射角色。
- 审计：`actor` 由"请求体自由字符串"改为**当前登录用户**（请求体 `approver` 字段保留但被服务端覆盖），
  这是 1.1.0 已登记的管理面风险（`product-plan` §8）的收口。
- 前端：设置页新增用户管理（admin 可见）；无权限的按钮禁用并给出原因，不作为安全边界。

### 3.5 C-e 分组管理与批量下发

- 分组 CRUD 页（1.0.0 起分组已有数据模型与下发支持，一直缺 UI）。
- 分组选择器下发：把"选组 → 生成/下发"接进编辑器与任务中心。
- 批量下发：多选 Collector → 逐实例生成独立任务（D6），任务中心按批次聚合展示。

### 3.6 C-f 体验补强

- 暗色模式：主题 Token 化（`ConfigProvider` 主题 + `localStorage`），不引入新依赖。
- EN 快速开始：`README.en.md`（主文案保持中文），与中文 README 互链。

## 5. 里程碑拆分（每步独立可测可发布）

| 步 | 内容 | 门禁 |
|---|---|---|
| C-a | 时间线（端点 + 前端 + 用例） | Go 单测（200/404/405/排序）+ vitest + UI E2E + `e2e.sh` 断言 |
| C-b | 审计导出（含导出自审计） | Go 单测（CSV 表头/BOM、越限 400、非法参数 400）+ e2e 断言 |
| C-c | F-18 巡检 + F-19 聚合 | 巡检单测（超时收口/正常态不误伤）+ 聚合前后一致性对照 |
| C-d | RBAC | 角色矩阵表驱动测试（viewer 无法审批、approver 无法管用户）+ 旧部署零回归用例 |
| C-e | 分组 UI + 批量下发 | 单测（批量 = N 个独立任务、部分失败不影响）+ UI E2E |
| C-f | 暗色 + EN | UI 冒烟（切主题不丢状态）+ 文档链接检查 |

## 6. 不做 / 延后

- **SSE / 流式输出**：1.1.0 已按设计延后；1.2.0 若要做得先定"断线重连与审计对齐"口径，暂列 1.3.0 候选。
- 多实例联邦、Helm、插件化、告警/Grafana 联动：1.3.0。
- 密钥托管（Keyring/Vault）：不引入，沿用环境变量 fail-closed 契约。

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| RBAC 改动登录语义，误伤既有单管理员部署 | 中高 | D4 零回归开关 + 旧配置引导管理员用例 + 迁移幂等 |
| 权限判定放前端被绕过 | 中 | 判定只在服务端中间件；前端仅展示态 |
| 批量下发放大故障面 | 中 | 逐实例独立任务 + 逐个生效确认（沿用 1.1.0 口径），失败互不影响 |
| 巡检误伤正常中间态任务 | 中 | 阈值可配 + 仅超时才收口 + 审计写明"巡检"来源 |
| 导出大表拖垮实例 | 中 | 行数上限 + 流式写出 + 超限 400 |

## 8. 验收映射（评审后逐项对照）

- C-a：任务详情能"回放"出每一次状态迁移与间隔时长；未知任务 404；非 GET 405。
- C-b：导出文件可直接用 Excel 打开且与页面筛选一致；超限给明确中文错误；导出动作本身留痕。
- C-c：人为造一个停留 `applying` 的超时任务，巡检后转 `failed` 且有审计；正常任务不受影响。
- C-d：`viewer` 调审批接口 403；`approver` 调用户管理 403；单管理员旧部署行为不变。
- C-e：批量下发 3 个实例 → 3 个独立任务，其中 1 个失败不影响其余。
- C-f：主题切换不丢登录态与路由；EN 文档与中文 README 互链。
