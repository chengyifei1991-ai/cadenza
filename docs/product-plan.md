## 1. 产品定位

**Cadenza = 开源 OpAMP 统一管控台**：一条命令跑起全栈（Go 后端 + `go:embed` 内嵌 React 前端），
让运维工程师与平台团队**看得见 Collector 集群、改得动采集配置、放得心走审批、找得回历史版本**，
并让 AI 助手成为"对话生成配置 → 校验 → 审批 → 下发"流水线的自然入口。

- 卖点一句话：**"用大白话改采集配置，先审批后下发，全程可回滚可审计。"**
- 差异化窗口：官方 OTel 生态缺少"开箱即用 + LLM 原生"的社区管控端，Cadenza 以
  OpAMP 协议兼容 + AI 双出口（MCP / 内置 Agent）切入。
- 非官方声明、Apache-2.0、社区治理文档已就绪，本阶段延续该定位（见
  [GOVERNANCE.md](../GOVERNANCE.md)）。

## 2. 已拍板决策（2026-09-05 产品评审会）

| # | 决策点 | 结论 | 影响 |
|---|---|---|---|
| D1 | 部署形态 | **单二进制内嵌前端**（`go:embed` 打包；开发期 Vite proxy 前后端分离） | 后端需新增静态挂载（P0-1）；放弃纯前后端分离的独立 CORS 部署路线 |
| D2 | 目标用户 | **面向社区开源用户**（1.0.0 同时服务个人实验与小型团队） | 安全默认值、开箱即用演示、onboarding 进 1.0.0 范围 |
| D3 | 鉴权范围 | **MVP：单管理员登录**；approver 绑定登录用户 | 后端补登录/中间件（P0-3）；RBAC 排 1.2.0 |
| D4 | 前端技术栈 | **React + TypeScript + Vite**（Ant Design 生态） | 见 [web-frontend-prd.md](./web-frontend-prd.md) 选型 |
| D5 | MVP 优先级 | **控制台优先，AI 助手并行** | 页面骨架同时含操作面与对话面；深度先保"下发/审批/回滚"主链路 |

## 3. 用户与核心场景

| Persona | 核心任务（Job-to-be-done） | 对应模块 |
|---|---|---|
| **SRE / 运维工程师**（主力） | 看集群健康；给某台/某组改配置；审批他人提交的变更；出事一键回滚 | Dashboard、Collectors、配置编辑器、任务/审批中心 |
| **平台 / 工具链团队** | 批量接入管理；审计合规留痕；把管控能力接进自家平台 | Audit、REST / MCP 双出口、分组管理（1.2.0） |
| **AI 原生用户**（差异化人群） | 不手写 YAML，自然语言生成/优化配置并跟踪到生效 | AI 助手（Cadenza Copilot） |

## 4. 1.0.0（GA）范围冻结面

### 4.1 做（In Scope）

| 模块 | 范围 |
|---|---|
| 认证 | 单管理员登录（登录页 + HttpOnly 会话 + 管理面保护）；`WEB_AUTH_MODE=off` 供本地/演示免登 |
| 控制台 | 仪表盘（健康/任务聚合）、Collector 列表/详情、配置编辑器（YAML + 校验 + 保存下发）、版本历史与回滚、任务中心（状态筛选/详情/审批/拒绝）、审计日志 |
| AI 助手 | 会话列表与历史回读、对话生成/优化、生成结果 diff 预览、任务联动追踪、LLM 不可用降级提示 |
| 体验 | 中文主文案 + EN 文案骨架、空/载/错三态、桌面优先响应式、单二进制开箱即用 + 演示数据（onboarding） |

### 4.2 不做（Out of Scope，排期明确到 1.2.0+）

- RBAC / 多租户 / OAuth、SSO（1.2.0）
- Collector 分组管理 UI 与批量下发（1.2.0，Store 层已具备）
- MCP 鉴权 token（1.1.0，MVP 期间 MCP 端点维持现状并文档声明风险）
- 聊天流式输出 / SSE（1.1.0 可选）
- 移动端、完整 i18n、主题定制（1.2.0 打磨项）
- `upgrade_collector`（协议 Beta，等 Collector 侧配合，UI 只读展示 Beta 标记）

## 5. 信息架构与页面地图

```
登录
 └─ 主布局（侧栏导航）
     ├─ Dashboard           集群健康 / 任务聚合 / 待审批提醒
     ├─ Collectors          列表（分页/状态过滤/搜索）
     │   └─ 详情           概览 | 当前配置 | 版本历史(回滚)
     ├─ 任务中心            全部任务（状态/类型筛选）→ 详情(diff/审批/拒绝)
     ├─ 审计                审计日志（时间/动作/actor 过滤）
     ├─ AI 助手             会话列表 + 对话 + 生成结果卡片 + 任务联动
     └─ 设置/关于           鉴权模式·LLM 链路健康·后端版本·演示数据
```

### 6.1 首个特性包：1.1.0 backlog

1.1.0 收敛自各里程碑评审遗留项（review-m1 / review-m2 / review-m3m4）与 4.2 Out-of-Scope 回填，
均为独立小步、不破坏 1.0.0 对外协议面：

- **MCP 鉴权 token**：`/mcp` 接入 bearer token 校验，消除"外部 LLM/IDE 可触发审批"的公开风险（公网部署前必选项）。
- **任务 ↔ 会话硬绑定**：generate/optimize 落任务时回写 `session_id`，任务详情与 AI 助手可按会话关联任务（替代文本正则"尽力而为"提取）。
- **后端筛选与分页**：任务中心（状态/类型/目标）与审计（动作/actor/时间区间）筛选后端化；超长会话消息分页/截断。
- **任务级 diff 服务端化**：分组目标任务提供代表实例/模板化 diff（diff 不再仅限单实例）。
- **会话流式输出 / SSE（可选）**：`/chat` 改流式返回，缓解长生成体感卡顿。
- **埋点与量化**：引入变更生效时长、下发成功率、回滚 MTTD 等运维效率指标的最小埋点。

## 7. 北极星指标与成功标准

- **可用性闭环**（1.0.0 GA 门槛）：从"发起配置变更"到"Collector 生效"全链路可在一个 Web 页面内无脚本完成。
- **上手成本**：全新用户按演示脚本 ≤30 分钟跑通（接入一个 Collector + 完成一次带审批的下发）。
- **采纳信号**（1.0.0 GA 后 90 天观察）：GitHub star 增长、Docker pull 数、Issue 中"装不起来"类占比 < 30%。
- 运维效率类指标（变更生效时长、下发成功率、回滚 MTTD）在 1.1.0 引入埋点后再量化，MVP 不空转指标。

## 8. 主要风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 管理面安全：审批/下发无身份边界 | **高** | M0 即落地登录中间件；approver 从自由字符串改为当前登录用户；`WEB_AUTH_MODE=off` 仅限本地/演示且文档显著警告 |
| MCP 审批入口无鉴权（外部 LLM/IDE 可触发审批） | 高 | MVP 风险接受并在文档声明；1.1.0 补 MCP token；若实测暴露于公网应提示用户先行部署在可信网络 |
| LLM 不稳定伤害口碑 | 中 | 复用后端故障隔离语义：UI 呈现"智能体不可用，可直接手动操作"，操作面与 AI 面解耦 |
| 前后端契约漂移 | 中 | M0 建立 OpenAPI 契约文件，前端类型由 `openapi-typescript` 生成；接口变更走契约先行 |
| 单维护者 + 开源冷启动 | 中 | M4 onboarding/演示数据不省；页面即活文档；延续 all-contributors 流程 |
| 多实例部署（注册表/审批/会话状态共享） | 低（1.0.0） | 明确 1.0.0 单实例约束写入 README；1.3.0 专项解决 |

## 9. 遗留待决问题（不阻塞 M0，需在使用中定案）

1. `WEB_AUTH_MODE=simple` 默认策略：未配置密码时启动报错（fail-closed）还是本地自动生成一次性密码打印日志。
2. `web/` 是否直接并入本仓库（推荐：monorepo，便于 embed 与 CI 单仓库发布）。
3. 演示数据（demo seed）是否默认注入（推荐：独立 `--demo` 开关 + 一键清库）。
4. 文档语言：README 保持中文主文案，1.0.0 GA 后补 EN 快速开始（社区采纳所需，已排入 1.2.0 完整 EN 文案）。
